DS WEB 2.0 conventions for new components (designer, 2026-10-19; see page "Modular Components - Landing" `16056:20149`): each component gets a "DS Card - <Name>" frame (Inside Title bar card with Specification / Menu / Overview links; sections "Component variants - for use", "Semi components - don't use", "Opis"), **its own spec page named after the component** (e.g. page "Segmented Control" `16064:25572`, page "Feature Tiles" `16077:174465`, each holding "DS Card - spec"), a box in "Overview - Modular Components - Landings" (`16057:20398`, Specification + Component links) and a link in the "Inside - DS Card - Menu" main component (`2264:34732`, section "MC - Landing"). **Every gap, padding and radius must be bound to a token** (e.g. Spacing/static/space-4…16, Spacing (Layout)/*, Radius/static/*); no raw values. Each `Size=` variant is a thin wrapper (Fill) around "<Name> - main component <size>" kept in a "Main component - don't use" section; edit the main component, not the variant. Give every size's main component the same layer structure and names (e.g. Feature Tiles › tiles › Feature Tile / …), otherwise Figma drops text and nested-variant overrides when someone switches Size. Use as few Size variants as possible and let width be Fill: one variant per layout change, named by its lowest breakpoint (1024+ covers 1024 and 1366, 600+ covers 600 and 800, 320+ covers 360 and 320).
